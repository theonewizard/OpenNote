# Compatibility corpus

Hand-made Markdown cases (testing strategy §3). Every read and write path in OpenNote must
reproduce each `note.md` byte for byte.

Layout: `vaults/<case>/note.md` plus `vaults/<case>/expected.json`. A case that needs a
whole vault (paths, Obsidian files) holds a `vault/` directory instead of `note.md`.
`expected.json` keys, all optional, filled in as the extractors land:

| Key | Meaning |
|---|---|
| `frontmatter` | Parsed properties, or `null` when there is no frontmatter or it is invalid |
| `frontmatter_error` | `true` when a frontmatter block exists but is not valid YAML |
| `links`, `embeds`, `tags`, `external_urls` | Extraction results (Phase 1 Task 5) |

Real vaults are never committed. Point `OPENNOTE_COMPAT_VAULT` at a private vault for a
local read-only run. The 10 MB note is generated by a test fixture, not committed.
