- R130: the prototype's retention window is counted in sequence numbers, not days, so the simulation can expire cursors without a clock (I6); retention in days is P5-07.

- R132 (CodeRabbit, follow-up): the external-change guard of Task 8 and storage contract §4 had a window between the hash check and the `rename` in which an external save is replaced and lost. The replacement is now `renameat2(RENAME_EXCHANGE)` and the displaced file is checked afterwards and preserved when it is not the base; filesystems without it (NFS, some RWX volumes) fall back to the old order with a startup warning and a note in the deployment guide. Cost if wrong: a `ctypes` call in `fsio.py` and a Linux-only path; the Apple clients use `NSFileCoordinator`.
- R133 (CodeRabbit, inline): Task 4 splits `edit_properties` into the key check plus `splice_keys`, which the Task 13 merge calls directly, so a clean merge can carry a change to `title`, `cssclasses` or any user key; user edits stay limited to `tags`, `aliases`, `id`, `opennote`.
