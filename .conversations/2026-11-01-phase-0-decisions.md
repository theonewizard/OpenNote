Why Trivy over the rest: it already carries Red Hat's status per finding (its RHEL feed is Red Hat's OVAL v2 plus the Security Data API; `--ignore-unfixed` is documented as shorthand for `--ignore-status affected,will_not_fix,fix_deferred,end_of_life`, and not_affected and under_investigation findings are never reported), the job summary needs no permission, and the change is two run steps and one file. SARIF upload to code scanning is free here and gives a persistent alert list with dismiss reasons, but needs `security-events: write`, a new pinned action, has no expiry, and the fingerprinting churns on changed lines; it stays the add-on if Flemming wants the Security tab. Grype can gate on `--only-fixed` and report the rest, but is a second scanner with a second database, its exit-code documentation conflicts (1 against 2) and its ignore rules have no expiry. OSV-Scanner documents container coverage for Alpine, Debian and Ubuntu only. Docker Scout and Snyk need an account and a token in CI. Red Hat's own CSAF/VEX files are the place to read the reasoning when writing a `statement`, not a CI tool. Caveats kept: the Trivy pages are 0.67 snapshots while CI pins 0.76.0 (confirm the flags on the first run; `fixed` is an accepted `--ignore-status` value per the page's own example); a job summary lasts as long as the run log; the filesystem report is largely redundant with `pip-audit --strict` and `npm audit`. Cost if wrong: two non-gating steps and a file, removable in one commit.
